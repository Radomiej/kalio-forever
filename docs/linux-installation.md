# Linux runtime installation and validation

The standalone Linux x64 runtime includes Node, the API, SQLite dependencies and
the embedded web UI. It does not require the desktop WebKit/FUSE packages.
The bootstrap needs Bash, tar, coreutils, Python 3 and curl or wget. OpenSSL is
also required when checking an Ed25519 release signature.

From a checkout containing these scripts:

```bash
bash scripts/install-release.sh --version 1.0.2 --install-root "$HOME/.local/share/kalio" --no-launch
"$HOME/.local/share/kalio/bin/kalio" serve
```

Omit `--version` to resolve the latest stable release through `api.github.com`.
The bootstrap verifies the selected archive's SHA-256 and size against the
release manifest before installing. The published v1.0.2 manifest is unsigned;
its integrity is checked using HTTPS and SHA-256. A signed manifest requires a
trusted public key supplied with `--public-key /path/to/public-key.pem` and must
pass signature verification. Do not obtain a trust key from an untrusted archive.

The sibling `install.sh` is used when running from a checkout. A standalone piped
bootstrap downloads the installer from the selected release tag, so its behavior
is that of that release. Prefer the checkout scripts when testing unreleased
installer fixes.

The default installation root is `${XDG_DATA_HOME:-$HOME/.local/share}/kalio`;
`KALIO_HOME` or `--install-root` can select another root. The stable launcher
sets the correct home even for a custom path containing spaces and follows
`current.json` after updates. The data and `.env` survive reinstalls. Runtime
archives are staged before replacement, and an active runtime lock prevents
replacement of a running application.

Use `serve` on headless Linux, or `start --no-open`. The embedded UI and API use
port 4016 by default. Set `KALIO_PORT` for a different port. Check
`/api/health` and run `bin/kalio doctor` to verify the actual runtime version,
SQLite driver and embedded UI. An installation message is not a health check.

The updated CLI forwards SIGINT/SIGTERM to its server and releases the runtime
lock after shutdown. The updater selects Linux `.tar.gz` assets, verifies their
manifest and switches the version pointer while preserving data. Save active
work before using `update --force`; process ownership is checked before stopping
the runtime. These CLI/updater fixes require a runtime archive rebuilt from this
branch. The original v1.0.2 archive still contains its old CLI/updater.

## Reproduce the Linux checks

```bash
pnpm install --frozen-lockfile
pnpm build
node --test scripts/linux-installer.test.mjs scripts/linux-cli.test.mjs scripts/linux-updater.test.mjs scripts/runtime-dependencies.test.mjs
node scripts/build-runtime-package.mjs --platform linux --runtime node --output release
node scripts/smoke-linux-runtime.mjs --archive release/kalio-runtime-1.0.1-linux-x64.tar.gz --output output/linux-runtime-smoke.json
```

Use the archive version generated by the current checkout. The smoke runner
creates an isolated installation with a random port, checks health and embedded
HTML, creates a session, writes/reads a small Node project through the VFS API,
runs its tests, stops the server, restarts it and verifies persistence. It writes
a JSON receipt and fails on missing readiness or a surviving runtime lock.
This project is a deterministic API smoke fixture, not an LLM-generated project.

`ci.yml` runs lifecycle regressions and builds/tests a real Linux Node archive.
Its `quality-gate` requires the Linux runtime job. The Linux release workflow
also smoke-tests the Node archive before upload. Bun archives remain available,
but the added runtime smoke job specifically validates Node.

## Local model comparison

Ollama is supported through its OpenAI-compatible `/v1` endpoint. A local model
does not require a paid API key. Use `LLM_API_KEY=ollama` as a non-secret
compatibility marker, and set the actual installed model and endpoint. Do not
leave `mock` in the API-key or base-URL fields: those values select mock mode.

```bash
OLLAMA_HOST=127.0.0.1:11434 OLLAMA_MODELS=/path/to/models OLLAMA_NO_CLOUD=1 OLLAMA_MAX_LOADED_MODELS=1 OLLAMA_NUM_PARALLEL=1 ollama serve
node scripts/local-model-benchmark.mjs --pull --models qwen3:4b,qwen2.5:3b,llama3.2:3b --output output/model-benchmark/results.json
```

The benchmark executes six cases per model: arithmetic through a tool, Unicode
file write/read and a small Node project, each prompted in English and Polish.
It records actual tool calls, responses, durations and failures. Generated
project tests must execute, and independent fixed acceptance assertions must
also pass. Results marked `blocked` or `failed` are not successful model tests.
The tools in this harness are bounded test tools; passing them does not prove
all Kalio tools work. Test a selected model through Kalio separately before
claiming application-level agent readiness.

On a restricted cloud network, enable `registry.ollama.ai` and the exact model
blob-storage hosts reported during download. GitHub release discovery and pull
requests also need `api.github.com`. Do not bypass a denied proxy destination.
Keep TLS, checksums and package-signature verification enabled. Heavy model
downloads are opt-in via `--pull`; CI tests the harness without downloading LLMs.
