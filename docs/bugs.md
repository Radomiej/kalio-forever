# Bug Log

## 2026-06-21

- `scripts/stack-manager.mjs` could not start a managed QA stack because `C:\Projekty\kalio-forever\.kalio-stack\logs\backend.log` was locked, which caused `EPERM` on `openSync()` and blocked random-port QA startup.
- The managed QA state can report `provider=mock` while `GET /api/llm/config` still returns a live `xiaomimimo` provider from the database, so mock/local QA can silently drift onto a live credential.
- `apps/kalio-web` build fails on `SessionPanelList.tsx` because TypeScript cannot resolve `@tanstack/react-virtual`'s `@tanstack/virtual-core` dependency through the current workspace link layout, so the random QA stack cannot finish its frontend build until that link is made explicit.
- `stack:stop` on Windows can fail at `taskkill` for the managed QA backend/frontend PIDs even after the stack is otherwise healthy, so the process sometimes needs a manual `Stop-Process -Force` cleanup before the stop command succeeds.
- `npm.cmd run test` failed in `packages/@kalio/types` because the `ArchitectureGraphProjection.nodes[]` contract test still expected the pre-`sessionId` node shape after `sessionId?: ID` was added to the shared projection type.
- `npm.cmd run test` now reaches `apps/kalio-api` but fails `architecture-durable-graph.spec.ts`: reconstructed `final-artifact` nodes receive `sessionId="...-finalizer"` while the regression expected `"...-final-artifact"`.
- `npm.cmd run test` also timed out `raapp-versioning.service.spec.ts` case `rollback -> re-approve produces correct semver and accumulated history` at 30000ms during the full backend suite.
- `npm.cmd run test:e2e` failed on the random-port Playwright stack: build/start succeeded, but the suite ended with `115 passed`, `24 failed`, `23 skipped`, and `13 did not run`; many failures share the same symptom where seeded or newly created sessions do not appear as `[data-testid="session-item"]` in the Talk sidebar.
- Fixed QA launched with `--use-env-llm` can report `provider=xiaomimimo source=env` at `/api/llm/config` while the effective env credential is empty or invalid, and the baseline `Architecture Debate` run then fails inside Router with `401 Unauthorized`.
- Live OpenRouter proof is currently blocked in this environment because `OPENROUTER_API_KEY` is not present in process env, `.env`, or `.env.test`; the requested `nvidia/nemotron-3-ultra-550b-a55b:free` model still requires a Bearer API key.
- Fixed: `POST /api/test-support/tool-confirmations/seed-replay` no longer returns `404` on the built QA stack. QA now enables `KALIO_ENABLE_TEST_SUPPORT=true`, while prod keeps it disabled.
- Fixed: stale HITL replay could restore a pending confirmation without enough durable correlation to settle it after a stale click. `RuntimeToolActivity` now carries `requestId`, and the FE store tombstones locally settled confirmation requests so delayed snapshots cannot resurrect old confirm buttons.
- Fixed: managed QA state now has one shared contract in `scripts/stack-state.mjs`; `start-qa.ps1`, `stack-manager status --json`, live credential activation, LLM probe, paid-readiness, and AC-13 QA startup all read `.tmp\qa-stack\qa-stack-state.json` instead of the legacy `.kalio-stack` path.
- Fixed: fixed-port web builds no longer depend on stale build-time `VITE_API_URL` / `VITE_WS_URL` for official app ports. `kalio-web` now derives `5188 -> 3016`, `5288 -> 3316`, and `6188 -> 4016` from `window.location`, while random-port stacks still use build-time env.
- Fixed: finalizer prompts for architecture workflows could balloon by replaying router messages that already embedded incoming graph outputs. Finalizer objectives now use compact incoming-event summaries and router decision summaries.
- Fixed: executing pre-created architecture router/finalizer sessions through `SubagentRuntimeService` overwrote their technical metadata, hiding them from workflow conversation surfaces. Runtime context updates now preserve architecture run/schema/slot metadata and mark technical nodes visible.
- Fixed: durable graph replay could produce `arch-arch-*` node session ids when the replayed run id was already prefixed. Graph projection and replay now normalize architecture session ids.
- Fixed: after F5, frontend workflow reconstruction could compare raw run ids with replayed `arch-*` ids as different runs and could omit router/finalizer `sessionId` from fallback host-message traces. Timeline and Canvas now reopen router/finalizer sub-conversations after reload.
- Fixed: OpenRouter live-gate scripts could silently seed `--provider openrouter` with a stale generic `LLM_API_KEY` from a different configured provider, producing a false credential activation and a later `401 Missing Authentication header` during completion smoke. Activation/probe now require `OPENROUTER_API_KEY` in that mismatch case and fail locally before network calls.
- Fixed: fixed QA `-UseMockLLM` could still use an active DB live credential, so `/api/llm/config` drifted from stack state `provider=mock` to `provider=openrouter source=db`. `start-qa.ps1 -UseMockLLM` now passes `--force-env-llm`, and `stack-manager` records `forceEnvLlm` in status.
- Fixed: `agentflow:paid-readiness` always required Web Search even for non-research Architecture Debate release gates, adding unrelated Perplexity blockers. Web Search is now required only with `--require-web-search` / `AGENTFLOW_REQUIRE_WEB_SEARCH=1`, and forced-env QA skips non-effective DB credential smoke.
- Fixed: `pnpm qa` reused existing dist by default, so fixed-port QA on `5288` could verify stale frontend/backend code. `start-qa.ps1` / `pnpm qa` now build by default; `-SkipBuild` / `pnpm qa:fast` is the explicit reuse path.
- Fixed: the baseline workflow E2E only opened one branch transcript, so regressions could still hide notes for other sub-agents. The test now opens every branch sub-conversation from Canvas and requires visible non-empty transcript content for each one.
- Fixed: the baseline workflow E2E did not prove per-node terminal status and initially assumed a single router card. It now asserts every router card, every branch agent card, and the finalizer expose `data-status="completed"` before and after reload.
- Fixed: HITL confirmation on built QA could execute the first deterministic `vfs_write` and then immediately surface a second pending `vfs_write` for the same mock trigger. The mock provider now treats the deterministic HITL `vfs_write` trigger as idempotent after a prior tool result or assistant tool call, and `tool:result` clears any matching pending confirmation if invalidation races.
- Fixed: the workflow release E2E still allowed weak proof for sub-agent notes and technical node logs. The baseline now ties each branch transcript to its role label, opens every router/finalizer technical session, checks visible latest-action text on router/branch/finalizer cards, and uses a realistic timeout for the 5-branch mock workflow.
- Fixed: Execution Graph route nodes for architecture branches carried `branchSessionId` only inside the payload, so the inspector could show node details but could not render `Open child chat`. Route nodes now expose top-level `sessionId`, root graph nodes prefer durable API `node.sessionId`, final artifact maps to the finalizer session, and the baseline E2E opens graph child chats after reload.

## 2026-06-22

- `node scripts/stack-manager.mjs status --json` can still report QA state `provider=mock model=mock forceEnvLlm=false` while the same running QA stack returns `/api/llm/config -> provider=xiaomimimo source=db` and `/api/credentials/active` is set. Release tooling must treat live API config as authoritative until the managed-stack state contract is fixed.
- Fixed: `stack-manager start --backend-port 3316 --frontend-port 5288` could report success against already-occupied ports because freshly spawned children died with `EADDRINUSE`, but health checks passed against stale listeners already bound to those ports. State then captured dead wrapper PIDs, so `status`, `stop`, and `release:workflow-gate` became untrustworthy. `stack-manager` now refuses unmanaged occupied target ports, refreshes managed PIDs from live listener port owners, and reports `unmanaged listeners` when fixed QA/prod ports are occupied without state.
