# Bug Log

## 2026-06-28

- Fixed: the AAA runtime contract slice added typed workflow reason/error/evidence/decision contracts and migrated the backend Architecture Runtime / AgentFlow adapter control-plane away from `message.includes(...)`, `error.message` branching, and ID-prefix runtime matching for retry, finalization, stop, max-step, max-node-visit, CLI/subagent, RAApp, chat snapshot, and durable replay paths.
- Fixed: durable architecture replay now primarily joins persisted sessions through `runtimeContext.architectureContext.architectureRunId` and messages/tool calls through `architectureRun.runId` or `architectureRunId`, rather than `sessionId`/`message.id` fragments.
- Fixed: vector-store schema migration no longer classifies duplicate-column state through SQLite error text; it checks `PRAGMA table_info` before running `ALTER TABLE`.
- Fixed: `string-business-logic` audit now treats typed `WorkflowErrorCode`, `WorkflowReasonCode`, and `runtimeDecision.reasonCode` comparisons as valid while flagging runtime ID-prefix parsing as HIGH. False-positive `typeof errorMessage === 'string'` display-field narrowing is ignored.
- Fixed: frontend Execution Graph/session projection fallback paths no longer infer architecture run/session state from `message.id`, `toolCallId`, `taskId`, or `session.id` prefixes. They now use `architectureRun`, tool args `architectureRunId`, exact tool-call correlation, and `runtimeContext.architectureContext` metadata.
- Fixed: graph routing no longer accepts prose `route_to(...)` as a production control-flow signal. LLM-originated graph route decisions must now arrive through structured `ArchitectureRouterOutput` with `nextAction='route_to'`, `targetNodeId`, and `response`; integration tests cover rejection/acceptance loops with the structured contract.
- Fixed: durable graph replay no longer derives event ids by parsing `toolCallId` prefixes. Workflow envelope tool calls now carry typed `architectureEventId`, and durable replay falls back to opaque ids rather than decoding id structure.
- Fixed: router/finalizer trace rendering could crash with `Cannot read properties of undefined (reading 'replace')` when a projected architecture trace step lacked `content`. Trace display cleanup now normalizes missing content and keeps fallback summaries display-only.
- Fixed: CLI streaming progress was correlated only by `callId`, so the current CLI stream could not be reliably attached to the chat turn lifecycle. `cli_agent:progress` now carries `turnId` through session runtime, pipe runner, PTY runner, and FE CLI child projection state.
- Fixed: architecture router/finalizer consumers now prefer typed `RunSubagentResult.structuredOutput` for `ArchitectureRouterOutput` and final artifact status before legacy assistant-text JSON fallback.
- Fixed: provider-native structured output now flows through `LLMStructuredOutputRequest`, `ILLMSource`, `LLMTurnRuntimeService`, `LLMServiceAdapter`, `StreamChatOptions`, and OpenAI-compatible providers via `response_format.json_schema`; architecture router/finalizer slots request typed JSON-schema contracts before legacy assistant-text fallbacks.
- Fixed: CLI child projection no longer derives `agentId` from arbitrary session titles. It prefers typed `SessionRuntimeContext.cliAgentContext.agentId`; title parsing remains only as a documented legacy fallback.
- Fixed: `scripts/code-audit/run-audit.mjs`, `scripts/code-audit/aggregate.mjs`, and `scripts/code-audit/audit-scripts.test.mjs` now emit and verify a dedicated `string-business-logic` warning section. The audit no longer treats only silent catches and `any` usage as control-plane smells; it now reports message-text and free-form text branching in business code.
- Fixed: the new audit detector is covered by regression tests and intentionally ignores typed-contract style comparisons such as `status === 'done'` in production code plus all test files. The warning is aimed at free-form text parsing (`message`, `content`, `prompt`, `text`, `name.toLowerCase()`, `id.startsWith()`), not at valid discriminated unions.
- Historical audit cluster, backend fixed in this slice: `apps/kalio-api/src/modules/agent-flow/architecture-agent-flow.adapter.ts` previously finalized and interpreted architecture runs through many `message.includes(...)` branches.
- Historical audit cluster, backend fixed in this slice: `apps/kalio-api/src/modules/architecture/architecture-runtime.service.ts`, `architecture-graph-runtime.ts`, and `architecture-role-executor.ts` previously classified stop/retry/exhaustion paths from free-form message text.
- Historical audit cluster, backend primary fixed in this slice: `apps/kalio-api/src/modules/architecture/architecture-durable-graph.ts` previously correlated runs through `id/sessionId/content` fragments. Remaining schema-name prompt parsing is legacy projection fallback, not runtime routing.
- Historical audit cluster, backend fixed in this slice: `chat.runtime-snapshot.ts`, `chat/subagent-runtime.service.ts`, `cli-agent/cli-agent-session-runtime.service.ts`, `memory/vector-store.service.ts`, and `raapp.controller.ts` previously branched on error message text.
- Fixed: frontend graph/chat projection code no longer has HIGH `string-business-logic` audit rows for Execution Graph/session tree ID-prefix behavior. Remaining string-driven frontend findings are lower-severity display/search/parser review leads.
- Biggest repo pain point: the architecture/agent-flow slice concentrates both the largest God Objects and most of the string-driven warning density. `architecture-graph-runtime.ts`, `architecture-runtime.service.ts`, `architecture-role-executor.ts`, and `architecture-agent-flow.adapter.ts` are simultaneously oversized, duplicate-prone, and semantically string-coupled.
- Biggest repo pain point: the repo still has critical-size files far beyond the stated limits, including `packages/@kalio/types/src/index.ts`, multiple backend architecture services, and large frontend pages/stores (`ObservabilityPage.tsx`, `executionGraphModel.ts`, `agentStore.ts`, `sessionStore.ts`). This makes typed contract extraction harder and encourages local string fallbacks.
- Biggest repo pain point: circular dependencies remain in both backend and frontend (`agent-flow-launch-context.ts ↔ architecture-runtime.service.ts`, `credentials.module.ts ↔ llm.module.ts`, `agentStore.ts ↔ cliChildProjection.model.ts`, `RAAppManager.Views.tsx ↔ RAAppCoreCard.tsx`). That boundary drift raises the chance of more ad-hoc string routing instead of explicit contracts.
- Biggest repo pain point: the audit report still shows recurring duplicate-code seams inside the architecture runtime and adapter layers. Shared parsing/classification helpers are not centralized enough, so the same string rules tend to spread instead of hardening once at the contract boundary.

## 2026-06-24

- Fixed: `scripts/stack-manager.mjs` still had an empty `catch {}` around the non-Windows fallback `SIGKILL` path. It now treats `ESRCH` as the expected already-exited process case and logs other kill failures with PID context.
- Fixed: `apps/kalio-api/src/modules/chat/chat.gateway.ts` still swallowed a failed lifecycle broadcast queue link with `.catch(() => undefined)`, so a transient ancestor/session lookup failure was invisible. The queue now logs the recovered failure and continues with later lifecycle events.
- Fixed: `scripts/code-audit/run-audit.mjs` emitted Node DEP0190 on Node 24 because it spawned `npx.cmd` with `shell: true` plus argument arrays. The audit runner now builds an explicit `cmd.exe /d /s /c ...` command on Windows with `shell: false`.
- Fixed: `scripts/code-audit/run-audit.mjs` produced a false-green `madge` circular-dependency result on Windows because the runner quoted `--extensions "ts,tsx"`, which made `madge` scan no TypeScript files and write `[]`. The Windows argument quoting now leaves comma-separated values unquoted and the regression test covers `--extensions ts,tsx`.
- Release blocker: backend module boundary rules are not currently enforceable. A subagent architecture scan found broad direct imports between `apps/kalio-api/src/modules/*` modules, including `chat.gateway.ts`, `chat.runtime-snapshot.ts`, `chat.service.ts`, and `chat.module.ts`, which conflicts with the repo rule that cross-module contracts should go through shared types or module APIs.
- Needs verification: direct filesystem tools are expected to access the real backend host filesystem, but release QA must prove they consistently enforce Settings `allowed_paths` before reading, listing, writing, or searching outside approved roots.
- Release risk: the public release browser gate does not yet cover the full shell surface. Current automated workflow gates focus on chat/workflow/HITL and need either tests or documented manual evidence for Landing, Quick Chat, Tools/RAApp/MCP, Mind, Observability, Settings, mobile layout, and RAApp tile execution.
- Fixed: mock QA could not prove RAApp catalog launches because an explicit `Use run_raapp with the exact id ...` launch prompt was echoed instead of converted into a `run_raapp` tool call. `MockLLMProvider` now emits `run_raapp` for explicit launch intents.
- Fixed: after that mock RAApp launch path emitted `run_raapp`, it repeated the same tool until the 8/8 tool limit and left the session pending. The mock provider now stops after a prior `run_raapp` result for the same id and emits a completion sentence.
- Release risk: at least one stored generated RAApp (`Quiz: Ciekawostki o Francji`) renders with a browser page error (`Unexpected identifier 'est'`) even though the RAApp runtime frame appears. Generated app quality needs a catalog validation pass separate from runtime correctness.
- Release risk: the production web build still emits Vite chunk-size warnings for chunks over 500 kB after minification. This is not a functional blocker, but public release should track bundle splitting/performance.
- Fixed: fixed-port QA started by `scripts/stack-manager.mjs` did not force fast mock streaming, unlike the random Playwright E2E stack. `release:workflow-gate` could fail at 180s while the architecture run completed a few seconds later. Mock fixed QA now sets `KALIO_MOCK_LLM_FAST=1` and records `fastMockLlm` in stack state.
- Release blocker: after the fast-mock and stop-follow-up fixes, a full `npm.cmd run release:workflow-gate` run timed out at the outer command limit after about 31 minutes without returning its own failure output. `scripts/workflow-release-gate.mjs` currently has no per-group timeout, so a hung Playwright group can make the release gate non-diagnostic.
